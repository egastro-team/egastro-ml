# ADR-0001. Зовнішній датасет для холодного старту

- **Статус:** запропоновано
- **Дата:** 2026-10-25
- **Задача:** EG-13 (Sprint 1, Spike)
- **Автор:** Taras Antoshchenko

## Контекст

Модулю «Розумний кошик» потрібні асоціативні правила вже на старті, коли власних замовлень єГастро ще немає (холодний старт, див. ML Canvas, ітерація 1). Потрібен відкритий датасет транзакцій-кошиків з продуктового ритейлу.

## Порівняння

| | **Instacart Online Grocery Shopping Dataset 2017** | **Groceries (R-пакет arules)** |
|---|---|---|
| Домен | онлайн-доставка продуктів, США | офлайн-продуктовий магазин (POS) |
| Обсяг | 3 421 083 замовлення, 206 209 користувачів | 9 835 чеків за 30 днів |
| Гранулярність товарів | 49 688 товарів → 134 aisles → 21 department | 169 категорій (без окремих товарів) |

| Ціни | **немає** | немає |
| Ліцензія | as-is, лише некомерційне використання (див. нижче) | у складі пакета arules (GPL-3) |

## Ліцензія

- **Instacart:** надається as-is для некомерційного використання. Навчальний проєкт під це підпадає, **комерційний запуск – це блокер**: до нього правила мають будуватися лише на власних замовленнях єГастро.
- Первинна сторінка умов (instacart.com/datasets/grocery-shopping-2017) вже недоступна (404); формулювання підтверджено за блогом Instacart (2017) і копіями умов у сторонніх репозиторіях. Перед комерційними рішеннями – перевірити юридично.
- **Groceries:** поширюється разом із пакетом arules під GPL-3; для навчального використання обмежень немає.

## Зміщення вибірки і непредставницькість для українського ритейлу

1. **Країна й асортимент.** США: інші товари, бренди, кухня (комплементарні пари на кшталт «паста → соус» переносяться, специфічні — ні). Назви англійською → потрібен мапінг на таксономію єГастро.
2. **Ціни й маржа.** У жодному датасеті немає цін → економічний ефект (≈ +15 грн на рекомендацію) з них не оцінити.
3. **Відбір користувачів Instacart.** Лише клієнти з 4+ замовленнями – лояльні, з повторюваними кошиками; нові покупці (основна аудиторія старту єГастро) не представлені.
4. **Час.** 2017 рік, без календарних дат → неможливі сезонність і ковзне вікно 90 днів; темпоральний спліт — лише за порядковим номером замовлення користувача.
5. **Groceries:** один магазин, один місяць, офлайн, лише категорії — придатний для прототипу, не для продакшн-правил.
6. **Українського відкритого датасету кошиків немає.** Пошук (Kaggle, data.gov.ua, Держстат) знайшов лише агреговану статистику Держстату — товарну структуру роздрібного товарообороту за групами (молочні, хлібобулочні тощо). Чеків чи кошиків у відкритому доступі немає; відкриття фіскальних чеків обговорювалося Мінцифри та ДПС, але як готовий набір даних не знайдено.

## Рішення

1. **Instacart — основний датасет холодного старту** для навчального проєкту. Правила для старту будуємо **на рівні aisle/department** і мапимо на категорії каталогу єГастро; правила рівня товарів використовуємо лише для аналізу (EG-14).
2. **Groceries — можна використовувати для швидкого прототипу та тестів** пайплайну (малий, без завантаження великих файлів).
3. **Перед комерційним запуском** – перехід на власні замовлення єГастро (поріг з канвасу: ≈ 5 000 замовлень); Instacart з продакшну прибираємо.

## Наслідки

- EG-14 (EDA) робимо на Instacart; темпоральний спліт – за `order_number`, не за датами.
- Потрібна таблиця мапінгу aisle/department → категорії єГастро (відповідальні: ML Engineer + BA).
- Оцінку ефекту в гривнях відкладено до появи власних даних (ціни єГастро).
- Конфіг `training.window_days` для Instacart не застосовний.
- Зміщення частково контролюємо: у EG-14 порівнюємо частки department в Instacart зі структурою роздрібного товарообороту продуктів за даними Держстату — так видно, які категорії «перекошені».

## Відкриті питання

- Чи з'являться відкриті фіскальні чеки (Мінцифри / ДПС) – тоді переглянути рішення.
- Юридична перевірка ліцензії Instacart, якщо проєкт вийде за межі навчального.
